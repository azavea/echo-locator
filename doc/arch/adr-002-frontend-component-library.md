# Frontend Component Library

## Context

*Note: Below copied with small edits from the initial component library evaluation, [found here in the Issue 603 discussion.](https://github.com/azavea/echo-locator/issues/603)*

We're rewriting the frontend [with React and vite](https://github.com/azavea/echo-locator/issues/599#issuecomment-2736833829) and should bring in a component library to ensure consistency across the frontend, speed up development, and handle things like accessibility and styling out-of-the-box. This is a mobile-first rewrite and users may be on slower network speeds or older devices as well as may be using assistive technologies. Knowing this the follow are important considerations:

- Accessibility
- Mobile-First and Responsiveness
- Internationalization (Spanish and Chinese translations in frontend)
- Library maintainability/stability
- Official figma kit (to bridge designs and development)

Another important consideration is the ability to have other developers jump on quickly, so the chosen library should have a well-documented library or strong team familiarity and examples.

We should move forward with using [Tailwind CSS](https://tailwindcss.com) for this frontend. We have growing familiarity with Tailwind and using a utility-first styling approach can help speed development and maintain consistency across the application, especially if taking advantage of its [theme variables](https://tailwindcss.com/docs/theme). Tailwind is also mobile-first and automatically removes all unused CSS when building for production so our final CSS bundle can be smaller.

Below are popular modern React component libraries to evaluate. Note that I've included headless component libraries. There are un-styled components that still have functionality and accessibility out-of-the-box, so the libraries are smaller and the components are free (though completely our responsibility) to customize.

## Decision

We will use `react-aria` in combination with `Tailwind CSS` for this project. We also should consider bringing in `DaisyUI` or `tailwindcss-react-aria-components` for faster styling.

`react-aria` component library was developed with accessibility prioritized and includes handling interactions on mobile beyond the ARIA standard. Additionally it includes internationalization, so it's best suited for an accessible mobile site with translations. Using a headless component library means upfront design and development time to add and maintain the styling, but `react-aria` includes [tailwind styling starter kits](https://react-spectrum.adobe.com/react-aria/getting-started.html#starter-kits) so it's less start-from-scratch than other libraries. Additionally we don't need complex components like charts or calendars and we can use tailwind theme variants to help maintain consistency and cut developer time.

There are styled libraries built using `react-aria` and `Tailwind`, namely `HeroUI` that appears to have an extensive library of components and in-progress figma kit. However, many of those are behind paywall (their "pro" version) and there has been historically poor performance of mobile/older devices with this library. Alternatives are `jollyui` (basically `shadcn` for `react-aria`) or `ariakit` but these are very new and too underdeveloped for us to consider.

We've recently used [DaisyUI](https://daisyui.com/) in another project, and we could potentially use their component classes in tandem with react aria components, [similar to this recommendation to use DaisyUI with HeadlessUI](https://daisyui.com/blog/how-to-use-headless-ui-and-daisyui/?lang=en). This would offer us pre-defined styles, the accessibility benefits of react aria components, as well as a figma kit to bridge wireframes and development. For now, however, we'll move forward with the styled starter kits provided by `react-aria` since one source will be more cohesive and easier to maintain. That styling can be available as copy-paste code or `react-aria`'s Tailwind CSS plugin, [tailwindcss-react-aria-components](https://www.npmjs.com/package/tailwindcss-react-aria-components).
